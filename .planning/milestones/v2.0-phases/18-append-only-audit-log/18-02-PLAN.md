auditLog({ actor_id, company_id, entity_type, entity_id, action, before, after }) from lib/services/audit.service.ts. Call after a successful repo write, never on ConflictError or ForbiddenError.

auditSnapshot(row) local helper analog lib/services/pm-assignments.service.ts: if !row return null; else { id, code, description, status, priority, due_date: row.due_date ?? null, owner }.

createRisk: after createRiskRepo returns, auditLog entity_type 'risk', entity_id String(created.id), action 'create', before null, after auditSnapshot(created). Same for createIssue with entity_type 'issue'.

updateRisk: always load prior via getRiskRepo before updateRiskRepo (needed for snapshots). After successful update:
- If fields.due_date is defined and String(fields.due_date) !== String(prior.due_date ?? ''), keep existing appendDueDateHistory plus auditLog action due_date_change (do not remove).
- If any own-property key in fields other than due_date is present, auditLog action 'update' with before auditSnapshot(prior) and after auditSnapshot(updated).
- due_date-only change: due_date_change only — do not also emit action 'update'.
- due_date omitted or unchanged and no other keys: no new audit (existing).
- due_date omitted but other fields (e.g. status) present: emit action 'update' only.

Mirror the same branching in updateIssue with entity_type 'issue' and getIssueRepo.

Existing unit test "does not append due-date history when due_date is omitted" currently expects getRiskRepo/getIssueRepo not to have been called. Change that assertion: get*Repo is now always called on update; still assert appendDueDateHistory is not called and auditLog is not called with action due_date_change; add that status-only updates call auditLog with action 'update'.

Do not audit deactivate twice. Do not edit repositories except via existing get/create/update functions.
