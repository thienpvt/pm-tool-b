# Phase 4 Plan 02: Close the Unauthenticated Export/Import Leaks

## Objective

Six routes currently accept a project id and return that project's full data with **no session
and no company check**. This plan closes all six. It is the highest-value security work in the
milestone and runs immediately after the substrate for that reason.

## Context — verified by direct inspection

`app/api/export/excel/[id]/route.ts` in its entirety is 18 lines: `await params` →
`generateProjectPlan(Number(id))` → return the xlsx buffer. There is no `getSessionFromRequest`
anywhere in the file. Any caller who guesses a project id receives the complete project plan.
`ppt`, `word`, `weekly-report`, `resource-plan`, and `import/resource-plan` share the shape.

Current signatures — none takes a company:

```
lib/export/excel.ts:103  generateProjectPlan(projectId: number): Promise<Buffer>
lib/export/ppt.ts:87     generateKickoffPPT(projectId: number, extras = {}): Promise<Buffer>
lib/export/word.ts:74    generateWordDoc(projectId: number, docType: string, docId?: number)
```

The export modules are already service-shaped — plain args in, `Buffer` out, repositories
imported, no `next/server`. The SVC-06 delta is the actor parameter and the assert. They keep
their `lib/export/` home; moving files would be churn, and CONTEXT scopes this phase to
behavior, not relocation.

Per the locked resolution, `export/weekly-report/[id]` and `import/resource-plan/[id]` get a
**thin wrapper + direct assert** rather than a full service extraction — they are
ExcelJS/body-driven with low logic leverage, and closing the leak is the entire objective.

<task id="04-02-01" type="tdd">
<action>
Add an `actor: { company_id: number | null; is_admin: number | boolean }` parameter to
`generateProjectPlan`, `generateKickoffPPT`, and `generateWordDoc`. Place it second, directly
after `projectId`, in all three — a consistent position prevents an argument-order mistake at
the call sites.

Each function calls `await assertProjectAccess(projectId, actor)` as its first statement,
before any repository read.

Replace the untyped `throw new Error('Project not found')` — `excel.ts:105` and `ppt.ts:97` —
with `NotFoundError`, so a missing project maps to 404 rather than a generic 500.

Do not otherwise alter document generation: the same repositories, the same ordering, the same
cell and slide content. This is an access gate bolted onto unchanged logic.

Write tests first for all three modules (none has a test file today): assert the repository
mocks are never called when the assert throws, assert ForbiddenError propagates for a
cross-company actor, and assert an admin actor still gets a document.
</action>
