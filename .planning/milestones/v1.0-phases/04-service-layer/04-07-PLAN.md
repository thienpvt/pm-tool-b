# Phase 4 Plan 07: Gap Closure — Collection Routes onto Services

## Objective

Convert the two collection routes — `app/api/projects/route.ts` and
`app/api/programs/route.ts` — from inline repository calls to services. This closes SVC-01, the
last completeness gap. The `[id]` detail routes for both were converted in 04-05; the
collection LIST/CREATE handlers were left.

The tenancy decision is the real content here: `POST /api/projects` and `POST /api/programs`
both resolve `companyId` inline in the route today —
`user.is_admin ? (body.company_id ?? null) : user.company_id`. That is an authorization
decision (which tenant may a caller place a resource into) sitting in the route. It belongs in
the service, where SVC-04 can enforce and test it.

**Current shape (both routes verified):**
- `projects/route.ts` GET: session → 401 (returns `[]`) → `listProjects(company_id, is_admin)`
- `projects/route.ts` POST: session → 401 → `companyId` resolved inline → `createProject(companyId, body)` → 201
- `programs/route.ts` GET: session → 401 (`[]`) → `listPrograms` + `projectCountsByProgram` in a
  `Promise.all`, merged via a `countMap` onto `project_count`
- `programs/route.ts` POST: session → 401 → `body.name?.trim()` 400 → `companyId` inline →
  `createProgram(companyId, body)` → 201

No live bug — both are session-gated and the company scoping is already correct. This is SVC-01
consistency (the service is the one home) plus SVC-04 (the tenant-placement decision tested).
