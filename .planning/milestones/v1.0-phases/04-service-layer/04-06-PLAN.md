# Phase 4 Plan 06: Gap Closure — Portfolio Sub-Resources onto the Service

## Objective

Wire the portfolio sub-resource routes onto `portfolio.service.ts`. The research explicitly
mapped all of them to the service (RESEARCH §119-139); the 04-04 plan executed only the main
`portfolio` GET, so the service was built for the summary while these 11 routes still call
repositories directly with authz that is session-present but company-unproven.

All are session-gated already (401 without a session), so this is consistency hardening, not
the live IDOR class — the risk is a company-scoping bug in ad-hoc inline logic that a grep can't
catch, plus one confirmed `String(e)` leak on `program-allocations` POST.

## The 11 routes (verified against the tree)

```
portfolio/budgets                          GET/POST
portfolio/budgets/[id]                     GET/PUT/DELETE   (GET aggregates allocations + category warnings via spendByCategory loop)
portfolio/budgets/[id]/allocations         GET/POST
portfolio/budgets/[id]/allocations/[allocId] PUT/DELETE
portfolio/budgets/[id]/categories          GET/POST
portfolio/budgets/[id]/categories/[catId]  PUT/DELETE
portfolio/members                          GET/POST
portfolio/members/[id]                     PUT/DELETE
portfolio/milestones                       GET
portfolio/program-allocations              GET/POST         (POST returns String(e) 500 today — HYG-02 improve)
portfolio/program-allocations/[id]         PUT/DELETE
portfolio/quota                            GET/PUT
```
