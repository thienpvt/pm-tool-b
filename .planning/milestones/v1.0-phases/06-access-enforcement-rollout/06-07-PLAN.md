# Phase 6 Plan 07: proxy.ts Runtime Finding (ROUTE-11)

## Objective

Resolve ROUTE-11 empirically: confirm whether `proxy.ts` executes in the deployed standalone
runtime, and record the finding. Phase 5 proved route-level enforcement does not depend on it;
this closes the loop with evidence.

**Do NOT modify proxy.ts.** CONTEXT locks this: record the finding only (fixing is outside
behavior freeze / a separate decision).

## Context

`proxy.ts` is correctly named for Next 16 (renamed middleware→proxy; `node_modules/next/dist/docs/.../proxy.md`
confirms a named `proxy` export is valid). Its `config.matcher`
(`/((?!_next/static|_next/image|favicon.ico).*)`) is registered in `functions-config-manifest.json`.

**Already-verified static evidence (run again to confirm):**
`.next/standalone/PyCharmMiscProject/pm-tool-b/.next/server/middleware-manifest.json` contains
`{ "middleware": {}, "sortedMiddleware": [], "functions": {} }` — proxy compiles into
`.next/server/middleware.js` but `sortedMiddleware` is empty, so the standalone server never
dispatches it.
