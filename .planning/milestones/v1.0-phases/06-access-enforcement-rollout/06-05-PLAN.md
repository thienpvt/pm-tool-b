# Phase 6 Plan 05: Convert the Program Routes

## Objective

Give `withProgramAccess` its Phase 6 consumers. The wrapper shipped in Phase 5 with zero
consumers (threaded for Phase 6 per the locked decision). Converts the 3 program-scoped routes
onto it, plus `portfolio/program-allocations` onto plain `withAuth`.

Behavior-freeze: these routes already gate (Phase 4 added session + assertProgramAccess /
assertProjectAccess). This is a wrapper-conversion, not new denials.

## Context

`withProgramAccess` (`lib/http/with-program-access.ts:19`) composes withAuth + calls
`assertProgramAccess(ctx.params.id, ctx.actor)` + hands `ctx.program` (the row) to the handler.
Three consumers, different shapes:

| Route | Current wrap | Convert to |
|---|---|---|
| `programs/[id]` GET/PUT/DELETE | raw session + assertProgramAccess (via `getProgramDetail`/`updateProgram`/`deleteProgram` services) | `withProgramAccess` — the service's internal assert stays; the wrapper adds the route-level one (defense in depth, matches the projects tree) |
| `programs/[id]/project-allocations` GET/DELETE/POST | raw session + assertProgramAccess on programId; POST ALSO calls assertProjectAccess on body.project_id (T-04-22 write IDOR fix) | `withProgramAccess` for the program assert; **keep the inline `assertProjectAccess(project_id)`** on POST — the body value is unreachable to a wrapper |
| `portfolio/program-allocations` GET/POST | raw session, company-scoped (no [id] param) | plain `withAuth` — it lists/allocates across the company's programs, no single program id |
