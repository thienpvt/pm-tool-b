# Phase 6 Plan 06: The 401/403 Test Matrix

## Objective

ROUTES-09/10's proof: a **drift-checked invariant** that every non-public route requires a
session (401 on a null session) and that every `projects/[id]/**` route denies cross-company
(403). Plus the 3 report routes' missing test files from plan 06-03's scope.

The matrix must be a SINGLE table-driven spec that a future route cannot silently escape — a
glob-driven drift check is what turns "we wrote a test for each route" into "every route HAS a
401 assertion, forever."

## Context

**Current coverage:** 37 `route.test.ts` files exist; 33 assert 401, 27 assert 403. ~45 routes
have NO test file (the count the scout gave, overlapping with the now-gated 8 IDORs).

**The 401 mechanism to test:** every session-resolving path 401s at `with-auth.ts:55-56` (`if
(!user) return 401`) or in legacy routes via their own `getSessionFromRequest` check. Because
the wrapper 401s BEFORE reading params/body, the matrix needs only a dummy `params:
Promise.resolve({})` and no body — the null session short-circuits everything.

**Public routes (must NOT be in the matrix):** `auth/login`, `auth/logout`, `health`,
`demo-requests`, `parse-file-headers` (gated separately in 06-02 via rawBody but still 401s).
`auth/me` DOES check session — it goes in the matrix.

**vitest.config** already includes `app/**/*.test.ts` — no config change for `app/api/**/*.test.ts`,
only for `lib/http/*.test.ts` if the glob needs it (confirm).

repo/service mocks only where a route's import would trigger DB work at import time.

legacy-getSessionFromRequest). Assert status AND that no data layer was touched.
