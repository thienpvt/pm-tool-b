<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client.ts → api.resend.com | outbound HTTPS POST with Bearer token crosses the boundary |
| api.resend.com → client.ts | upstream JSON (untrusted) crosses back in and is zod-validated |
| client.ts → integrationErrorResponse → response body | error mapping renders fixed strings, never upstream raw bodies |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-03-07 | Tampering | resend/client.ts | high | mitigate | zod boundary validation (INTG-05/06); malformed 2xx → logged `IntegrationError{kind:'validation'}` → 502, never a partial id |
| T-03-08 | Information Disclosure | resend/client.ts, lib/api-errors.ts | high | mitigate | Only `data.message ?? data.name ?? 'Resend API error'` crosses to the client; raw bodies stay in `cause` server-side (matches today's behavior) |
| T-03-09 | DoS | resend/client.ts | medium | mitigate | 15s `withFetchTimeout` abort; timer cleared on success; timeout maps to kind 'timeout' → 502 |
| T-03-10 | Spoofing | resend/client.ts | medium | mitigate | Bearer token only ever read from `resolveResendCredentials()` result — env-only, precedence unchanged (INTG-08) |
| T-03-11 | Tampering | route.test.ts mocks | low | accept | Route test mocks client + resolver; client unit tests own the fetch behavior; no live Resend call in CI |

</threat_model>
