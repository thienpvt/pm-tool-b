## Design System

| Property | Value |
|----------|-------|
| Tool | shadcn |
| Preset | `b2fA` — base-nova, neutral, Geist sans, lucide, radius default |
| Component library | Base UI (shadcn base-nova) |
| Icon library | lucide-react (same as Sidebar) |

## Spacing Scale

Declared values (multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon–label gaps, badge padding |
| sm | 8px | Compact table cell padding (`p-2`), inline control gaps |
| md | 16px | Default section gaps (`gap-4`), Card internal spacing |
| lg | 24px | Page header margin-bottom, filter bar padding |
| xl | 32px | Main content horizontal padding on desktop |
| 2xl | 48px | Major section breaks between page zones |
| 3xl | 64px | Unused this phase |

**Exceptions:** Sidebar nav touch targets stay at existing `py-2` (~32px row height). Virtualized tracking row height fixed at **40px** (`h-10`) for window math. PM editor textarea min-height 80px.

**Page shell:** Match Phase 21 — `flex flex-col lg:flex-row min-h-screen bg-slate-50`, main `flex-1 p-4 lg:p-6 lg:p-8 overflow-auto`.

| Role | Value | Usage |

**Card styling:** `Card size="sm"` with default shadcn ring; optional `shadow-sm` on tracking summary strip only.

### Routes & NAV (22-CONTEXT D-01..D-02)

| Surface | URL (module) | Thin re-export alias | NAV label | Visibility | Icon (lucide) |
|---------|--------------|----------------------|-----------|------------|---------------|
| CPMO periods + config | `/weekly/periods` | — | **Weekly periods** | `roles.includes('cpmo')` | `CalendarDays` |

**Module root:** `modules/weekly/ui/`; thin re-exports at `app/weekly/**` and `app/projects/[id]/weekly-reports/[reportId]/page.tsx`.

### Periods page zones (top → bottom)

1. **Header** — title "Weekly periods", subtitle with period count
2. **Config card** — company weekly due schedule (GET/PUT `/api/weekly-periods/config`)
3. **Create period card** — ISO week input + primary create action (POST `/api/weekly-periods`)
4. **Period list** — compact table of existing periods with link to tracking for each row

**Focal point:** Config + create at top; period list secondary.

### Tracking page zones (top → bottom)

1. **Header** — title "Weekly tracking", period `Select`, export actions right-aligned
2. **Summary strip** — count chips from `counts` (obligated, submitted, draft, not submitted, overdue, late)
3. **Filter bar** — query params for GET tracking (status, lateness, pm, stage, rag, technology_council)
4. **Tracking grid** — virtualized table (`VirtualRows`) with row selection checkboxes for export
5. **Export bar** — format Select (xlsx / docx / pptx) + **Export pack** primary button

**Focal point:** Virtualized grid is primary; filters and export secondary.

### PM editor zones (top → bottom)

1. **Header** — period `display_name`, project name (link to `/projects/{id}`), status Badge, due date
2. **Read-only strip** — prev-week RAG Badge (not editable)
3. **Form sections** — single-column stacked Cards (see Editor Contract)
4. **Action bar** — sticky footer or bottom Card: **Submit report** (primary when draft/not_submitted), **Open correction** (when submitted and correction allowed per API), save-on-blur or explicit PATCH on field change (debounced)

**Focal point:** Form fields primary; submit/correct actions pinned at bottom.

## Component Contracts

### Company weekly config (periods page)

GET `/api/weekly-periods/config`; PUT on save.

| Field | Control | Notes |
|-------|---------|-------|
| Due weekday | `Select` 0–6 (Sun–Sat labels) | Map to `due_weekday` |
| Due time (UTC) | `Input` type time or text `HH:MM` | Maps to `due_time_utc` |

Layout: horizontal `flex flex-wrap gap-4 items-end` inside config Card. **Save schedule** primary button; toast on success/error.

### Create period (periods page)

| Field | Control | Validation |
|-------|---------|------------|
| ISO week | `Input` placeholder `2026-W05` | Client hint + server `YYYY-Wnn`; 409 → toast "Period already exists for this week" |

### Period list table

Columns: **Week** (`display_name`), **ISO week**, **Due at** (formatted UTC), **Actions** (link **Track submissions** → `/weekly/tracking?periodId={id}`).

Compact table classes match Phase 21:
- `TableHead`: `h-8 px-2 text-xs`
- `TableCell`: `p-2 text-sm`
- Wrapper: `overflow-x-auto`

### Tracking period selector

On mount: GET `/api/weekly-periods` for options. Default selected period = query `periodId` if valid, else most recent `iso_week`. Changing period refetches tracking GET.

### Tracking summary chips

Six inline badges from `counts`: Obligated, Submitted, Draft, Not submitted, Overdue, Late. Label `text-xs font-semibold`, count `text-sm`. Zero counts still render "0".

### Tracking filter bar

AND filters forwarded as query params (22-CONTEXT D-07, API D-05):

| Key | Control |
|-----|---------|
| status | Select: All / not_submitted / draft / submitted / overdue |
| lateness | Select: All / on_time / late |
| pm_user_id | Select from distinct PMs in current rows (or empty until loaded) |
| stage | Select L0–L5 + All |
| rag | Select Green / Amber / Red / All |
| technology_council | Checkbox |

Layout: `flex flex-wrap gap-2 items-end` in bordered bar. **Apply filters** refetches; no persist API.

### Tracking grid (virtualized)

**Component:** `modules/weekly/ui/shared/VirtualRows.tsx` — in-repo only, no npm (D-08).

| Property | Value |
|----------|-------|
| Row height | 40px fixed (`ROW_HEIGHT = 40`) |
| Container | `overflow-y-auto` with explicit `max-h-[calc(100vh-280px)]` or similar |
| Window | Render visible slice + 5-row buffer above/below |
| Table | shadcn `Table` header sticky; body rows inside virtual window |

**Columns:** Checkbox (export select), Project (link `/projects/{id}`), Code, Stage, PM, Status (Badge), Overdue (yes/no Badge), RAG (Badge), Lateness, Tech council (icon or Yes), **Open report** (`/projects/{project_id}/weekly-reports/{report_id}`).

**Selection:** Header checkbox selects all **filtered** rows currently in memory (not only visible window). Export POST uses selected `project_ids`; disable export when selection empty.

**Proof test (D-09):** Component test renders 150 mocked rows; assert `tbody tr` count ≤ 30 (windowed), data length 150.

### Export pack (tracking page)

POST `/api/weekly-periods/[periodId]/export` body `{ project_ids, format }`.

| Control | Behavior |
|---------|----------|
| Format Select | xlsx (default), docx, pptx |
| Export pack | Primary `bg-blue-600`; disabled when no selection or in-flight |
| Download | Reuse `modules/dashboards/ui/shared/downloadBlob.ts` |
| Filename | From `Content-Disposition` header |

### PM editor form (single-column Cards)

Sections top → bottom (22-CONTEXT discretion: single column):

| Section | Field(s) | Control |
|---------|----------|---------|
| RAG | This week RAG | `Select`: Green, Amber, Red, Not applicable |
| Highlights | highlights | `Textarea` rows=3 |
| Completed work | completed_work | `Textarea` rows=3 |
| Next week goals | next_week_goals | `Textarea` rows=3 |
| Nearest milestone | nearest_milestone, nearest_milestone_id | Text + optional id (PATCH allowlist) |
| RAID dependency | raid_dependency | `Textarea` rows=2 |
| Leadership support | leadership_support | `Textarea` rows=2 |

**Prev-week RAG:** read-only Badge in header strip; never PATCH (D-05).

**Draft save:** debounced PATCH (300ms) on field change when status allows edit; 409 on submitted snapshot → toast **Report is submitted — open a correction to edit.** (D-05).

**Submit:** POST `.../submit`; surface `SubmitValidationError` field list inline under form + toast summary.

**Correct:** POST `.../correct` when status is submitted; then form editable per API rules.

**Do not** build a separate RAID grid editor (D-06); show server validation paths only.

### Auth & forbidden (all pages)

- NAV hidden for unauthorized roles
- API 401/403: centered main content — spinner while loading, then forbidden panel (Copywriting Contract)
- Do not redirect; in-page forbidden like Phase 21 dashboards
- Viewer on CPMO pages: 403 panel
