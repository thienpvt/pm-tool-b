# Phase 23 — UI Design Contract

> Visual and interaction contract for CPMO document catalog/templates, PM Confluence checklist, CPMO compliance dashboard, and CPMO audit log viewer. Generated by gsd-ui-researcher; consumed by gsd-ui-checker, gsd-planner, gsd-executor.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | shadcn |
| Preset | `b2fA` — base-nova, neutral, Geist sans, lucide, radius default |
| Component library | Base UI (shadcn base-nova) |
| Icon library | lucide-react (same as Sidebar) |
| Font | Geist Sans (`--font-sans` in `app/globals.css`) |

**Installed components to use:** `Card` (prefer `size="sm"`), `Button`, `Badge`, `Table`, `Select`, `Input`, `Textarea`, `Label`, `Checkbox`, `Separator`, `Collapsible` (audit row expand) or native `<details>` if Collapsible not installed. Toasts via `sonner` (already wired in Sidebar).

**Do not install:** chart libraries, JSON tree widgets, virtualization npm packages, new shadcn blocks, third-party registries.

**Source:** Match Phase 21/22 (`21-UI-SPEC.md`, `22-UI-SPEC.md`); `components.json` present with base-nova preset; `23-CONTEXT.md` D-01..D-12.

## Spacing Scale

Declared values (multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon–label gaps, badge padding |
| sm | 8px | Compact table cell padding (`p-2`), inline control gaps |
| md | 16px | Default section gaps (`gap-4`), Card internal spacing |
| lg | 24px | Page header margin-bottom, filter bar padding |
| xl | 32px | Main content horizontal padding on desktop |
| 2xl | 48px | Major section breaks between page zones |
| 3xl | 64px | Unused this phase |

**Exceptions:** Sidebar nav touch targets stay at existing `py-2` (~32px row height). Virtualized row height fixed at **40px** (`h-10`) when `VirtualRows` is used. Audit JSON `<pre>` panels min-height 80px, max-height 240px with internal scroll.

**Page shell:** Match Phase 21/22 — `flex flex-col lg:flex-row min-h-screen bg-slate-50`, main `flex-1 p-4 lg:p-6 lg:p-8 overflow-auto`.

### Catalog page zones (top → bottom)

1. **Header** — title "Document catalog", subtitle with active item count
2. **Create catalog card** — name, purpose, stage, mandatory checkbox, apply_to_in_flight checkbox (post only when API accepts field), primary **Add catalog item**
3. **Catalog table** — list GET `/api/document-catalog`; row actions: **Edit**, **Retire** (PATCH `active=false`)
4. **Templates card** — visible when a catalog row is selected (click row or `?catalogId=` query). GET `/api/document-templates?catalog_id={id}`; create form POST with URL-only `template_url`

**Focal point:** Catalog table primary; templates secondary panel below or beside on `lg:` breakpoint.

### Compliance page zones (top → bottom)

1. **Header** — title "Document compliance", subtitle with filtered project count
2. **Filter bar** — stage, status, rag, program (GET query keys from `COMPLIANCE_FILTER_KEYS`)
3. **Compliance grid** — projects with compliance Badge; link project name → `/projects/{id}/document-checklist`

**Focal point:** Compliance grid primary; filters secondary.

### PM checklist page zones (top → bottom)

1. **Header** — title "Document checklist", project name (link `/projects/{id}`), subtitle with item count
2. **Checklist table** — one row per catalog item; inline or row-expand editor for PATCH fields
3. **Item editor** (inline expand or side panel) — status, Confluence URL, conditional approved fields, N/A reason, optional notes

**Focal point:** Checklist table + per-item save primary.

### Audit page zones (top → bottom)

1. **Header** — title "Audit log", subtitle "Append-only company audit trail"
2. **Filter bar** — entity_type, entity_id, from, to, limit; **Apply filters** primary
3. **Audit table** — actor, time, entity, action; expandable before/after JSON panels

**Focal point:** Filtered audit table primary.

## Component Contracts

### Compact table classes (all pages)

Match Phase 21/22:
- `TableHead`: `h-8 px-2 text-xs font-semibold`
- `TableCell`: `p-2 text-sm`
- Wrapper: `overflow-x-auto`

### Catalog list table

GET `/api/document-catalog` (auth read; CPMO write for mutations).

| Column | Source | Notes |
|--------|--------|-------|
| Name | `name` | Retired rows: `text-slate-400 line-through` when `active=false` |
| Stage | `stage` | L0–L5 or ALL |
| Mandatory | `mandatory` | Yes/No Badge |
| Status | `active` | Active / Retired Badge |
| Actions | — | **Edit** opens inline form or dialog; **Retire** confirms then PATCH `active: false` |

**Create form fields:**

| Field | Control | API field |
|-------|---------|-----------|
| Name | `Input` required | `name` |
| Purpose | `Textarea` rows=2 | `purpose` |
| Stage | `Select` L0–L5, ALL | `stage` |
| Mandatory | `Checkbox` | `mandatory` |
| Apply to in-flight projects | `Checkbox` | `apply_to_in_flight` (include in POST/PATCH body only when supported) |

**Edit form:** Same fields; PATCH `/api/document-catalog/[id]`. Re-activate allowed if API returns `active: true` on PATCH.

**Retire:** Confirmation dialog — "Retire this catalog item?" body "Existing checklist rows remain; new projects won't receive this item." Primary destructive **Retire item** → PATCH `{ active: false }`.

### Templates panel (catalog page)

GET `/api/document-templates?catalog_id={selectedId}`.

| Column | Source |
|--------|--------|
| Name | `name` |
| Type | `document_type` |
| Version | `version` |
| Effective | `effective_date` formatted |
| Template URL | external link (`text-blue-600`, `target="_blank"`, `rel="noopener noreferrer"`) |

**Create template form** (CPMO, POST `/api/document-templates`):

| Field | Control | Validation |
|-------|---------|------------|
| Catalog | pre-filled from selection | `catalog_id` |
| Name | `Input` | required |
| Document type | `Input` | required |
| Effective date | `Input` type date | ISO date |
| Guidance | `Textarea` rows=2 | optional |
| Template URL | `Input` type url | HTTPS required (`template_url`) |

Primary CTA **Publish template**. No file upload control (D-04, URL-only).

### PM checklist table

GET `/api/projects/[id]/document-checklist`.

| Column | Source | Notes |
|--------|--------|-------|
| Document | `catalog_name` | show Mandatory Badge when `catalog_mandatory` |
| Stage | `catalog_stage` | |
| Status | `status` | Badge with mapped label (see below) |
| Confluence | `confluence_url` | link or em dash |
| Actions | — | **Edit** expands row editor |

**Status Select values** (API enum as-is, D-11):

| API value | UI label |
|-----------|----------|
| `none` | None |
| `drafting` | Drafting |
| `pending_approval` | Pending approval |
| `approved` | Approved |
| `not_applicable` | Not applicable |

**Row editor fields** (PATCH `/api/projects/[id]/document-checklist/[itemId]`):

| Field | Control | When visible |
|-------|---------|--------------|
| Status | `Select` | always |
| Confluence URL | `Input` | always except hide requirement hint for none/drafting |
| Approved date | `Input` type date | status = approved |
| Approved by | `Input` (user id or name string) | status = approved |
| N/A reason | `Textarea` rows=2 | status = not_applicable |
| Notes | `Textarea` rows=2 | optional |

Primary CTA **Save checklist item**. On 400 `{ error, fields }`, render `fields` keys inline under controls in `text-red-600 text-xs`. No file input anywhere.

**Confluence link preview:** When URL valid HTTPS, show **Open in Confluence** text link (`text-blue-600`) below input.

### Compliance filter bar

GET `/api/dashboards/document-compliance` with query params:

| Key | Control |
|-----|---------|
| stage | Select L0–L5 + All |
| status | Select project status values + All |
| rag | Select Green / Amber / Red / Not applicable + All |
| program | Select from programs list (fetch `/api/programs` or reuse existing pattern) + All |

Layout: `flex flex-wrap gap-2 items-end` in bordered bar. **Apply filters** refetches; invalid unknown keys surface API validation error toast.

### Compliance grid

Response `{ filters, projects[] }` where each project has `compliance: 'compliant' | 'not_compliant' | 'not_applicable'`.

| Column | Source |
|--------|--------|
| Project | `name` link → checklist |
| Code | `project_code` |
| Stage | `stage` |
| Status | `status` |
| RAG | `rag` Badge |
| Compliance | `compliance` Badge |

Use `VirtualRows` when `projects.length > 100` (D-09); otherwise standard table body.

### Audit filter bar

GET `/api/audit` query params:

| Key | Control | Default |
|-----|---------|---------|
| entity_type | `Input` text | empty = all |
| entity_id | `Input` text | empty = all |
| from | `Input` type date | empty |
| to | `Input` type date | empty |
| limit | `Select` 50 / 100 / 200 | 50 |

**Apply filters** primary `bg-blue-600`. Show helper "Showing up to {limit} most recent entries."

### Audit table

| Column | Source | Notes |
|--------|--------|-------|
| Time | `created_at` | locale-formatted |
| Actor | `actor_id` | numeric id (API does not enrich display name) |
| Entity | `entity_type` + `entity_id` | `{type} #{id}` |
| Action | `action` | monospace `text-xs` |
| Details | expand toggle | chevron button |

**Expanded row (D-08, D-10):** Two-column grid on `md:` — **Before** and **After** labels `text-xs font-semibold`. Content:

```tsx
<pre className="text-xs font-mono whitespace-pre-wrap overflow-auto max-h-60 bg-slate-50 p-2 rounded border">
  {JSON.stringify(value, null, 2)}
</pre>
```

Use `null` literal for missing snapshot. **Never** use `dangerouslySetInnerHTML`. No PATCH/DELETE controls.

Use `VirtualRows` when row count > 100 (same 40px row height for collapsed rows; expanded row renders outside virtual window or disable virtualization when any row expanded — prefer: virtualize collapsed list only; expanding scrolls row into view and renders detail below row).

### Auth & forbidden (all pages)

- NAV hidden for unauthorized roles
- API 401/403: centered main content — spinner while loading, then forbidden panel (Copywriting Contract)
- Viewer on CPMO pages: 403 panel
- PM checklist: viewer read-only or 403 per API `withProjectAccess` rules
- Do not redirect; in-page forbidden like Phase 21 dashboards

## Implementation Notes (for executor)

1. Module roots: `modules/documents/ui/` (catalog, compliance, checklist pages + shared hooks), `modules/audit/ui/` (audit viewer). Thin re-exports at `app/documents/catalog/page.tsx`, `app/documents/compliance/page.tsx`, `app/projects/[id]/document-checklist/page.tsx`, `app/audit/page.tsx`.
2. Do **not** overwrite v1 `/projects/[id]/documents` page or API (23-CONTEXT D-06, Phase 17 D-01).
3. Reuse `modules/weekly/ui/shared/VirtualRows.tsx` for compliance/audit long lists; copy to `modules/documents/ui/shared/` or `modules/audit/ui/shared/` only if cross-module import is awkward (D-09).
4. Audit JSON: `JSON.stringify(value, null, 2)` inside `<pre>`; never `dangerouslySetInnerHTML` (D-08).
5. Checklist PATCH: map API field errors from `{ error, fields }` to inline messages; status enum values must match API snake_case on wire, human labels in Select only.
6. Catalog retire = PATCH `{ active: false }`; do not DELETE.
7. Template create retires prior version server-side — UI only POSTs new version; no separate retire button unless API exposes it.
8. Sidebar: insert Catalog, Compliance, Audit log after Weekly tracking block; role-gate `cpmo` only.
9. Project hub: add Document checklist quick link; keep existing Documents link to v1 dump.
10. Component tests with mocked `fetch` for each page shell (403, empty, populated) per 23-CONTEXT scope.
11. Match admin/programs and Phase 21/22 table density — no spacious padding overrides.
12. Primary buttons: `className="bg-blue-600 hover:bg-blue-700 text-white"` or shadcn default primary if already blue-600 themed.
