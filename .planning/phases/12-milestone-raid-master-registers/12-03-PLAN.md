appendDueDateHistory({ entity_type: 'risk' | 'issue', entity_id: string, old_due, new_due, changed_by }): INSERT into raid_due_date_history. Analog: insertAuditLog. No update/delete exports.

updateRisk / updateIssue: after assertProjectWriteAccess, load prior via getRisk/getIssue. Run uniqueness checks from 12-02. Call update repo. Then if fields.due_date !== undefined and String(fields.due_date) !== String(prior.due_date), appendDueDateHistory and auditLog action due_date_change with before/after due_date only (D-06, D-10). Skip append when the normalized strings are equal (Pitfall 5).

listOpenRisks(projectId) and listRisks(projectId): compute today inside the repo as new Date().toISOString().slice(0, 10) so project-report.service callers stay signature-compatible. SELECT includes (due_date &lt; today AND status IN ('Open','In Progress')) AS is_overdue. ORDER BY: CASE status when Open or In Progress then 0 else 1; CASE priority High 1 Medium 2 Low 3 else 4; CASE is_overdue then 0 else 1; due_date NULLS LAST; id (D-07). listOpenRisks already filters Open/In Progress so the status CASE is redundant there but the priority plus overdue CASE must apply. Mirror listIssues / listOpenIssues. Keep listNotClosedByPriority as-is (report page contract).

listHighOpenRaid(companyId: number | null): UNION ALL High + Open/In Progress risks and issues with entity_type discriminator, same tenant join as listPortfolioMilestones. Return { records, count } where count === records.length using row count not COUNT(DISTINCT project_id) (D-08). Two High risks on one project plus one High issue must yield count 3.

listTechnologyCouncilIssues(companyId): SELECT issue rows plus project_name where technology_council IS TRUE and status IN ('Open','In Progress'), same tenant filter (D-08).

raid-masters.service.ts already exports upcoming/overdue from 12-01. Add listHighOpenRaid and listTechnologyCouncilIssues here. Do not add them to portfolio.service (D-15).
