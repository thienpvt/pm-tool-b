# Phase 6 Plan 02: Gate the 8 Live IDORs

## Objective

Close the last genuinely-live anonymous holes in the codebase: the 8 multi-tenant routes with
**no session check and no ownership check**. This is the security point of Phase 6 — the reason
ROUTE-10's 401-on-every-non-public-route requirement exists.

These are **new denials** (401 where previously open), so they ship **shadow-first** per
ROUTE-08: deployed with `ACCESS_ENFORCEMENT=shadow` so real-world legitimate traffic is observed
before the flip to enforce. (Plan 06-01 built the shadow flag.)

## The 8 IDORs (verbatim from the live codebase)

Each is anonymous today — no `getSessionFromRequest`, no ownership check, and `proxy.ts` is dead
in deployment so nothing catches them upstream.

| Route | Methods | Risk today |
|-------|---------|-----------|
| `app/api/bug-import-mapping/route.ts` | GET/POST | anonymous read of every tenant's import templates + anonymous create |
| `app/api/bug-import-mapping/[id]/route.ts` | DELETE | **anonymous bare-id DELETE** — `deleteBugMapping(id)`, wipes a tenant's template |
| `app/api/import-mapping/route.ts` | GET/POST | anonymous read/create |
| `app/api/import-mapping/[id]/route.ts` | DELETE, PUT | **anonymous DELETE + anonymous write** |
| `app/api/jira/jql-presets/route.ts` | GET/POST | anonymous read/create of JQL presets |
| `app/api/jira/jql-presets/[id]/route.ts` | DELETE | **anonymous bare-id DELETE** |
| `app/api/jira/sync-mappings/route.ts` | GET/POST | anonymous read/write |
| `app/api/parse-file-headers/route.ts` | POST | **anonymous multipart file upload + parse** |

(`app/api/config/route.ts` — the half-open GET — is handled in plan 06-04 alongside the rest of that file; see note.)

## The tenancy-column constraint (record explicitly)

These tables (`lib/db.ts`):
- `timeline_import_mappings (id, name, mappings_json, created_at)` — **no company_id** (:437)
- `bug_import_mappings (id, name, mappings_json, created_at)` — **no company_id** (:475)
- `jira_jql_presets (id, name, jql, created_at)` — **no company_id** (:478)
- `jira_sync_mappings (id, mappings_json, created_at)` — **no company_id** (:480)

There is nothing to scope by. `withAuth` (require a valid session, 401) is the **ceiling** this
milestone can enforce without a schema migration. The residual risk — an authenticated user
from company A can still read/delete company B's template rows — must be explicitly recorded in
the summary and STATE as a **v2 company_id-migration follow-up**, NOT silently dropped.

<task id="06-02-03" type="tdd">
<action>
Gate `parse-file-headers/route.ts` (anonymous multipart upload) with `withAuth` +
`opts.rawBody: true`.

This route does `await req.formData()` to accept a multipart file upload — NOT `req.json()`.
Without `rawBody`, the wrapper's auto-parse would return 400 'Invalid JSON' before the handler
runs and consume the body stream. Use `opts.rawBody: true` (from plan 06-01) so the handler
calls `req.formData()` itself.

The handler body (formData extraction, `file` null check → 400 'No file', header parsing) is
preserved byte-for-byte. Only change: wrap in `withAuth` with rawBody.

Route test: 401 with no session (handler's formData never reached); a session-authenticated
multipart upload works (mock the formData/File).
