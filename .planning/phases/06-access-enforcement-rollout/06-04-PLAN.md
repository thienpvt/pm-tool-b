# Phase 6 Plan 04: Convert Export/Import/Config Routes (ROUTE-04)

## Objective

Convert the 8 export/import/config/parse-neighbor routes onto the Phase 5 wrappers. All are
behavior-freeze: they already enforce something (Phase 4 gated them with session + assert); this
moves that enforcement INTO the wrapper. No new 403s — those were cut in Phase 4.

## Context

Phase 4 (plan 04-02) gated these routes with raw session + per-service/route assertions. The
shapes split three ways:

| Route family | Current shape | Wrap target | Body |
|---|---|---|---|
| `export/excel/[id]`, `export/ppt/[id]`, `export/word/[id]/[type]` | raw session + generator self-asserts (`generateXxx(id, actor)`) | `withProjectAccess` (idempotent extra assert) | ppt is POST JSON → opts.rawBody (it uses formData/body passthrough) |
| `export/weekly-report/[id]`, `export/resource-plan/[id]`, `import/resource-plan/[id]` | raw session + inline `assertProjectAccess` | `withProjectAccess` (assert moves INTO the wrapper — dedup) | import is multipart → opts.rawBody |
| `export/portfolio/members` | raw session, company-scoped (no project id) | `withAuth` (company scope keeps the service's own scoping) | GET |
| `config` | GET raw, POST admin-gated | `withAuth` for both paths (system, no id; POST keeps is_admin check) | POST JSON |

**The 3 generators keep their internal assert.** `generateProjectPlan(id, actor)` etc. call
assertProjectAccess inside lib/export — that's the Phase 4 SVC-06 leak-closure. withProjectAccess
in the route adds a second, redundant-but-idempotent `projectAccessRow` query. It's ~1 extra query
per export call, uniform across the wrapper model, and alternative (trying to skip the wrapper
assert for generator-self-asserting routes) would fragment the model for no real saving. Document
it in the summary; do NOT remove the generators' own assert (it's the defense-in-depth).
