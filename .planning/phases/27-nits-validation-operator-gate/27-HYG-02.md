# HYG-02 — Operator Acceptance: Anthropic Validation 502 (D-04)

**Date:** 2026-08-29  
**Decision:** Operator **accepts** HTTP **502** (not 500) when Anthropic returns malformed output that fails schema validation on the three GET report routes.  
**Code change:** None — existing behavior in `lib/api-errors.ts` is retained (D-04, D-06).

---

## Accepted Behavior

When `IntegrationError` has `kind: 'validation'` and `service: 'anthropic'`, `integrationErrorResponse` returns **502** even when the route passes `{ force500: true }`.

Non-validation Anthropic errors (upstream, timeout, network, auth) still honor `force500`: report routes get **500**, other routes get **502**.

**Rationale (INTG-06):** Shape mismatches must not surface as 500; the frozen report-route split still governs other error kinds. Validation is a post-phase error kind with no legacy 500 contract to preserve.

**Source:** `lib/api-errors.ts` lines 139–153 — `validation` branch escapes `force500`.

**Explicitly out of scope:** Reverting to 500, editing report handlers, or changing `force500` call sites.
