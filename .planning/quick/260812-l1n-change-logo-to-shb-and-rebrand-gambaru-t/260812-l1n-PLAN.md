  <action>
Create `components/brand/Logo.tsx` exporting a single default-free named component `Logo`.

Signature: `export function Logo({ className, onDark = false }: { className?: string; onDark?: boolean })`.

Body: render `next/image` with `src="/shb-logo.svg"`, `alt="SHB"`, `width={1350}`, `height={540}`, `priority={false}`, and `className={cn('w-auto', className)}` using the existing `cn` helper from `@/lib/utils`.

Aspect-ratio rule (this is the whole point of `w-auto`): call sites pass ONLY a height utility (`h-6`, `h-7`, `h-8`). Never pass a `w-*` utility. Passing a height with `w-auto` keeps the 2.5:1 ratio and also silences the next/image "modified one dimension but not the other" console warning — `w-auto` is what satisfies it. A `h-6 w-6` square slot would squash the wordmark, which is exactly the failure this component exists to prevent.

Contrast rule: the wordmark is navy `#2f2e79`, which is near-invisible on the `#0f172a` sidebar. When `onDark` is true, wrap the image in a white chip: `<span className="inline-flex items-center rounded-md bg-white px-1.5 py-1">`. This preserves both brand colors (an SHB requirement — do NOT use a `brightness-0 invert` filter, which would destroy the orange). When `onDark` is false, render the image bare with no wrapper chip.

This component is deliberately two-state, not a size/variant system — `onDark` is the only prop beyond `className` because it is the only thing call sites actually differ on.

Then wire the tracer path: in `components/layout/Sidebar.tsx`, delete the local `KoinoboriIcon` function definition (lines 20-34), add `import { Logo } from '@/components/brand/Logo';`, and replace BOTH usages — the desktop/drawer nav header (line 95) and the mobile top bar (line 336) — with `<Logo onDark className="h-6 shrink-0" />`. Both sit on `bg-[#0f172a]`, so both need `onDark`.
